Como proteger sua chave
e publicar no GitHub

O que sobe, o que fica, e por que a chave secreta nunca pode aparecer no código público

01 · O problema

A chave de API é como uma senha bancária

Se alguém encontrar sua chave de API, pode fazer chamadas no seu nome — e você paga a conta. Por isso ela nunca pode aparecer em nenhum arquivo público.

😱
Errado — Nunca faça isso
Chave no código
Colocar ANTHROPIC_API_KEY=sk-ant-... dentro do index.js ou do index.html. Qualquer pessoa que ver o repositório no GitHub encontra a chave e pode usá-la.
✅
Certo — Como fazemos
Chave no .env
A chave fica num arquivo separado chamado .env, que o .gitignore impede de subir ao GitHub. Só existe no servidor — nunca no repositório público.
⚠️
Caso real frequente
Bots vasculham o GitHub em tempo real procurando por chaves de API expostas. Em minutos após um commit descuidado, a chave é encontrada, usada e você recebe uma fatura inesperada. A Anthropic e outras empresas cancelam automaticamente chaves detectadas em repositórios públicos.
02 · Estrutura do projeto

O que cada arquivo faz

O projeto tem uma separação clara: código que pode ser público e segredo que nunca pode sair do servidor.

football-analyst-v2/ — estrutura completa 
football-analyst-v2/
│
├── server/
│   └── index.js        ✅ sobe ao GitHub   ← backend Node.js (sem a chave)
│
├── public/
│   └── index.html      ✅ sobe ao GitHub   ← interface do usuário
│
├── .env.example        ✅ sobe ao GitHub   ← template (sem chave real)
├── .gitignore          ✅ sobe ao GitHub   ← lista o que NÃO sobe
├── package.json        ✅ sobe ao GitHub   ← dependências do projeto
│
└── .env                ❌ NUNCA sobe       ← sua chave real aqui
💡
Por que o .gitignore funciona assim?
O arquivo .gitignore contém a linha .env — isso diz ao Git para nunca rastrear, nunca incluir e nunca enviar esse arquivo. Mesmo que você rode git add . (que adiciona tudo), o .env é ignorado automaticamente.
.env — conteúdo (fica só no servidor) 
# Este arquivo NUNCA vai ao GitHub
# Crie-o no servidor copiando o .env.example

ANTHROPIC_API_KEY=sk-ant-SUA-CHAVE-AQUI
PORT=3000

04 · Passo a passo

Do computador ao GitHub ao servidor

O fluxo completo de publicação — em ordem, sem pular etapas.

1
Criar repositório no GitHub
Acesse github.com, clique em "New repository", dê um nome (ex: football-analyst) e crie como público ou privado.
2
Enviar o projeto (sem o .env)
No terminal, dentro da pasta do projeto:
git init && git add . && git commit -m "primeiro commit" && git push
O .gitignore garante que o .env fique de fora automaticamente.
3
No servidor: clonar o repositório
No seu VPS ou serviço de hosting:
git clone https://github.com/seu-usuario/football-analyst
4
Criar o .env no servidor (só aqui)
Copie o template e preencha com sua chave real:
cp .env.example .env   # depois edite com sua chave
5
Instalar dependências e iniciar
npm install && npm start
Pronto. O app está rodando e a chave está protegida.
✅
Regra de ouro
O arquivo .env só existe no servidor. Nunca no GitHub, nunca no seu computador pessoal de forma permanente, nunca em e-mail ou mensagem. Se precisar passar a chave para alguém, use um gerenciador de senhas.
